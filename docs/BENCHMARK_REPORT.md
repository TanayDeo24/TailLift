# Benchmark Report

All numbers here trace to `artifacts/*.json`, generated by the scripts named
next to each figure. This document does not introduce any number that isn't
in an artifact file.

## 1. Dataset provenance
See `docs/DATA_PROVENANCE.md`. Summary: `newMedium.txt`, 1,439,823 tail→head
query pairs, binary relevance label (same clicked URL + rank ≤5 both sides,
per the original method). No raw AOL log, no timestamps, no user IDs present
anywhere in this repository.

## 2. Data cleaning
Query normalization: lowercase, whitespace-collapse (`src/mapping.py::tokenize`,
applied consistently in `scripts/audit_data.py`, `scripts/build_splits.py`).
1,439,823 rows parsed from `newMedium.txt`; 0 malformed rows found
(`artifacts/data_audit.json` -> `newMedium.n_malformed_rows`).

## 3. Sessionization
Not performed — no timestamp/user data exists. See `docs/SESSIONIZATION.md`
for the full justification.

## 4. Split methodology
Query-grouped, 70/15/15, seed 20260922, zero measured cross-split leakage
(vs. the original repository's own split, which had confirmed 4.3% leakage).
See `docs/SPLIT_METHODOLOGY.md`.

## 5. Frequency definition
Inherited from the original repository's own processing (`separator.py`,
`HEAD_LIMIT=150`, `TAIL_LIMIT<5`) — cannot be independently re-derived
because raw occurrence counts are not available locally. See
`docs/HEAD_TAIL_METHODOLOGY.md`.

## 6. Head/tail definition
Head = the 12,261-query `head150.txt` vocabulary. Tail = the 1,409,790
unique query strings in `newMedium.txt`'s tail column. Eligible tail (has
≥1 ground-truth positive head) = 116,655 (8.27%).

## 7. Primary task
Task A: tail query → relevant head query (query-to-query relevance mapping),
per the project brief's Section 16 framing. Chosen because it is the one
task this repository's surviving evidence (binary tail/head relevance pairs)
can directly and honestly support.

## 8. K decision
Primary K = 5. Secondary K = 1, 10 also reported throughout
(`artifacts/ladder_results.json`, every level's `agg` dict has hit@1/5/10 and
recall@1/5/10). K=5 chosen as a realistic "show up to 5 alternate/related
queries" product surface — not chosen by testing which K produced the best
number; frozen in `artifacts/frozen_config.json` before any test-split
evaluation.

## 9. Metric decision
Primary metric = MRR (mean reciprocal rank). Justified: the eligible
tail-query population is overwhelmingly single-relevant-target (median 1,
p90 1 positive head per tail query — `docs/DATA_PROVENANCE.md`), which is
exactly the regime MRR/Hit@K are designed for (Section 18 of the project
brief). nDCG was not used — there is no graded relevance signal in this
dataset, only binary.

## 10. Original baselines
`separator.py`'s Jaccard token-overlap similarity function was faithfully
preserved and adapted from the original pairwise classifier formulation into
full-index retrieval ranking (`src/mapping.py::LexicalMapper`) — this is
Level 0/1 in the ladder below. The original SVM ensemble's 78% accuracy
claim could not be verified or reproduced (no result artifact exists,
the entity-linking feature's external API is dead, and the script was never
actually wired to a data file present in the repository — see
`docs/QUERY_LOG_AUDIT.md`).

## 11. Mandatory modernization ladder

All numbers: `artifacts/ladder_results.json` (`agg` per level, per split),
consolidated in `artifacts/final_metrics.json`.

| Level | Description | Val MRR | Test MRR |
|---|---|---|---|
| 0/1 | Original Jaccard similarity, preserved and adapted to full-index retrieval | 0.1447 | 0.1474 |
| 2 | Semantic bi-encoder only (`multi-qa-MiniLM-L6-cos-v1`) | 0.1894 | 0.1897 |
| 3 | Lexical + semantic fusion (α=0.9) | 0.1933 | 0.1945 |
| 4 | Fusion + cross-encoder rerank (`ms-marco-MiniLM-L-6-v2`, depth=10) | 0.1878 | 0.1889 |
| 5 | Fusion + train-only support prior (β=0.25) | **0.2648** | **0.2661** |

**Architecture selection** (`artifacts/final_metrics.json` -> `architecture_selection`):
Level 5 selected — highest MRR on the full validation split, decided before
any test-split number was computed (Section 20/38/39 compliance).

**Negative result, reported honestly**: Level 4 (cross-encoder rerank)
underperforms Level 3 (fusion alone) on both validation and test. The
off-the-shelf MS MARCO passage-ranking cross-encoder does not transfer
cleanly to query-query mapping, at least not without task-specific
fine-tuning (out of scope here — see `docs/FINAL_REPORT.md` Limitations).
This is exactly the kind of finding Section 40's "negative results" and
Section 43's "reranker hurts" failure category ask to be preserved, not
hidden by quietly making the reranker the final system anyway.

## 13. Data-sparsity evidence
See `docs/SEARCH_QUALITY_DIAGNOSIS.md` §3, §5 and `artifacts/sparsity_correlation.json`.
Headline: the only available evidence-density proxy shows a near-zero
correlation with mapping quality (Spearman ρ=-0.026 vs. final MRR),
reported as a genuine null result rather than omitted.

## 14. Final intervention
Level 5: lexical Jaccard + semantic bi-encoder cosine similarity (min-max
normalized, fused with α=0.9 toward semantic) + a training-split-only
head-popularity log-prior (β=0.25), ranked over the full 12,261-query head
index, no candidate truncation, no cross-encoder. See
`docs/FINAL_ARCHITECTURE.md`.

## 15. Optimization
Validation-only search (Section 37-39): 2 embedding-model candidates ×
4 fusion-weight candidates, on a fixed 3,000-query random sample of the val
split (`artifacts/optimization_search_log.json`); then 3 support-prior-weight
candidates and 2 cross-encoder-rerank-depth candidates, same sample, same
best model/alpha held fixed. One search round, no refinement iteration was
needed (the first round's results were decisive: `multi-qa-MiniLM-L6-cos-v1`
with α=0.9 was the clear winner by a comfortable margin over
`all-MiniLM-L6-v2` at every α tested). Config frozen
(`artifacts/frozen_config.json`) before Phase B (full val + full test, one
pass, no retuning after seeing test numbers).

## 17. Coverage
Primary evaluation: 100% coverage (no abstention threshold applied — every
one of the 17,499 held-out eligible test tail queries receives a ranked
mapping). Secondary confidence-bucketed analysis
(`artifacts/coverage_analysis.json`): quality rises monotonically with a
top-1-fusion-score confidence signal (top quartile mean MRR 0.332 vs. bottom
non-trivial quartile ~0.222); a hypothetical 0.9 confidence threshold would
retain 82.2% coverage at mean MRR 0.298. Not deployed — reported to
characterize headroom for a future abstention policy only.

## 20. Offline intervention metrics
The primary MRR/Recall@K/Hit@K results above already are the offline

## 21. Latency
Inference-path benchmark, frozen final system (Level 5, no reranker), run
locally (not yet deployed — see `docs/DEPLOYMENT.md`): **P50 18.9ms / P95 21.8ms / P99
25.1ms**, cold start 13.2s (model+index load, measured once, excluded from
the percentiles). Protocol: 20 warmup + 300 measured requests, concurrency=1,
cycling a fixed 40-query set from the test split
(`artifacts/latency_benchmark.json`). For comparison, the rejected reranker
variant (Level 4) is both lower quality AND much slower: P50 42.7ms / P95
116.7ms / P99 123.7ms — over 5x the P95 latency for a system validation
rejected on quality grounds. The final system's speed advantage was not a
factor in its selection (validation MRR alone decided it) but is a welcome
consequence, not a tradeoff that had to be made.

## 22. Statistical reliability
Paired bootstrap, 5,000 resamples, seed 20260922, n=17,499 paired
observations (`src/metrics.py::paired_bootstrap_ci`,
`artifacts/final_metrics.json` -> `paired_bootstrap`). 95% CI on the
baseline→final MRR delta: [+0.1150, +0.1225] — comfortably excludes zero. No
small-sample caveat needed (Section 42): 17,499 paired observations is far
beyond typical minimums for a stable percentile bootstrap on a bounded
[0,1] metric.

## 23. Negative results
- Cross-encoder reranking (Level 4) reduces MRR relative to fusion alone
  (Level 3) on both validation and test — see §11.
- The available evidence-density proxy shows no meaningful correlation with
  mapping quality — see §13.
- A strong training-period popularity prior can override a correct literal
  lexical match for less-popular true targets (`docs/FAILURE_ANALYSIS.md`
  Category 2) — a real, disclosed weakness of the selected system, not
  smoothed over by the strong aggregate numbers.
